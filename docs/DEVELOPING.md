# Developing

- **Contract:** `docs/ARCHITECTURE.md` is the source of truth for the schema, API and business rules. When you
  change behaviour, update it in the same change. Add new behaviour as a short "Added:" section at the end.
- **Python:** 3.12 through uv, with the project in `app/pyproject.toml`. Run `cd app && uv run pytest -q`.
- **UI:** vanilla ES modules under `app/ui/js/`, with no build step and no CDN. Check syntax with
  `node --check app/ui/js/*.js`. To try a UI change without data, serve `app/ui` and open `/?mock=1`.
  `app/ui/mock/mock.js` answers every API call with invented data.
- **Database changes:** append a `_migrate_N` to `MIGRATIONS` in `app/finapp/db.py`. Never edit an old migration's
  effect on an existing database. Seeds stay generic. Household-specific rules belong in `data/personal_setup.json`
  (see `examples/personal_setup.example.json`).
- **Tests use invented data only.** No real account numbers, card digits, merchants or amounts. Fixtures live in
  `app/tests/fixtures/`, generated by `make_fixtures.py`. A test that needs household rules (a rent band, a one-off
  category) is marked `@pytest.mark.household` and gets `tests/fixtures/household_setup.json`. Tests that read real
  files from `data/` assert shapes only and skip when the file is absent.
- **Never commit data.** `data/` and statement file types (`*.pdf`, `*.xlsx`, `*.csv`, `*.db`) are gitignored outside
  the test fixtures. Keep scratch databases and real-data screenshots under `data/tmp/` or `data/screens/`.
- **Local dev server on a copy of your DB:** `scripts/review_server.sh fresh` serves a copy on :8795. It never uses
  `data/finance.db` itself.
